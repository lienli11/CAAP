# 远程启动与资源调度

**用户未来自行 clone 并启动；本轮没有远程部署、远程环境安装、科研训练或常驻 Agent。本地已完成基础包可编辑安装，未安装 research extra；当前科研调度仍为 future。**

## 1. 当前命令与 future 边界

从根仓运行以下自检；源码方式无需先安装 PyTorch，也无需联网安装基础包。本机已安装基础包时，也可使用 `.venv/bin/python -m caap`，不设置 PYTHONPATH：

```bash
PYTHONPATH=src python3 -m caap --help
PYTHONPATH=src python3 -m caap --version
PYTHONPATH=src python3 -m caap doctor
PYTHONPATH=src python3 -m caap plan-check --manifest plan/tasks.json
PYTHONPATH=src python3 -m unittest discover -s tests/unit -t . -v
```

默认 doctor 将完整 JSON 写入 stdout。可选保存报告时先创建派生报告目录，目标必须是**尚不存在的新文件**：

```bash
mkdir -p reports
PYTHONPATH=src python3 -m caap doctor --output reports/doctor.json
```

`--output PATH` 成功后 stdout 为空；父目录必须已存在，工具不会 mkdir。它原子创建新文件，拒绝覆盖已有文件或写入 caap 包目录；文件系统不支持安全发布时直接报错，不退回覆盖写。重复执行请换新的报告名，不删除旧报告来伪装新结果。

`--probe-torch` 仅在允许探测时使用；默认不 import torch，只读安装 metadata。实际探测通过 `python -I` 隔离子进程，标记 `scope=isolated_no_user_site_no_pythonpath`，忽略用户 site 与 PYTHONPATH；其 import_error 不等于当前进程未安装 torch，不能与 metadata 观察的环境混为一谈，也不会污染主进程：

```bash
PYTHONPATH=src python3 -m caap doctor --probe-torch --timeout 10
```

`--timeout` 默认 10 秒，分别限制每次外部查询，不是整个 doctor 的总时限。默认自检不训练、不加载真实权重、不下载包，也不授予 GPU 权限。

| **命令/结果** | **退出码与输出** | **不能推导** |
| --- | --- | --- |
| doctor 成功输出清单 | exit 0；GPU 缺失/失败/超时、torch import_error 均保留结构化状态 | 有可用 GPU、allocation 已授权或科研门禁通过 |
| doctor 输出失败 | exit 2；stderr JSON `status=output_error` | 自动换路径覆盖或继续提交半成品 |
| plan-check 清单有效 | exit 0；stdout JSON，含拓扑 waves/潜在写冲突 | 任务已实现或允许并行执行 |
| plan-check 清单/文件/JSON/依赖无效 | exit 1；stdout JSON | 缺任务可自动省略 |
| 参数错误 | argparse exit 2 | 自动忽略未知参数 |

`plan-check [--manifest plan/tasks.json] [--repo-root PATH]` 的 repo-root 默认 cwd，相对 manifest 按该根解析；没有 `--output` 参数。其报告明确 `document_graph_only=true/experiments_implemented=false`，潜在写冲突提示不自动使 valid=false，也不是并发授权。

标准库测试此时只验证已经存在的迁移/自检能力。更广 suite 中研究依赖缺失导致的 skip 必须记录，不能当作科学门禁通过；未来测试规格不能记成已运行用例。

**以下仅是 future 目标接口，当前不要执行：**

```text
python -m caap.tools.run_experiments --manifest runs/control/experiment_manifest.json --dry-run
python -m caap.tools.run_experiments --manifest runs/control/experiment_manifest.json
python -m caap.tools.collect_tables --manifest runs/control/experiment_manifest.json --out reports/full
```

`configs/experiments/full.json` 是版本化矩阵配置；future 冻结后生成 `runs/control/experiment_manifest.json` 执行快照，保存来源配置与 hash。若实现选择直接以配置路径作为冻结 manifest，必须满足同一不可变内容合同，不允许路径别名产生第二套科学键/状态。

未来统一 `python -m caap run` 如实现，只能委托同一受限调度器，不能形成第二套协议/状态。确切入口和参数以对应 F 任务实现、`--help` 与验收为准；本轮 CLI 不宣称支持 run/自动恢复。

## 2. 环境基线与兼容性

| **环境** | **可以做** | **不能自动推导** |
| --- | --- | --- |
| Python 3.9+，macOS/CPU | 标准库 doctor、plan-check、迁移测试 | CUDA、科学训练、七模型数值正确 |
| Linux/CPU 研究环境 | 获准的 CPU 单测、小型梯度/恢复夹具 | GPU 吞吐或显存预算 |
| Linux/CUDA allocation | 通过门禁后的 GPU 冒烟、计时和冻结任务 | 看见整机所有 GPU 就可全占 |
| macOS MPS | 明确测试支持的未来独立配置 | 与 CUDA 数值/性能等价，或已有 MPS 支持 |

基础 `pyproject.toml` 不强制重依赖；可选 `[research]` 范围为：

| **包** | **范围** |
| --- | --- |
| torch | `>=2.5,<3` |
| torchvision | `>=0.20,<1` |
| numpy | `>=1.26,<3` |
| Pillow | `>=10,<13` |
| tqdm | `>=4.66,<5` |

这些是候选兼容范围，不是每个版本随意组合都兼容。远端须根据 Python/架构、GPU 驱动、CUDA runtime 与 torch/torchvision 官方配对解析，再跑实际验收并冻结精确环境 lock/来源。Python 3.9 的基础自检支持不代表最新全部研究依赖仍支持 3.9；解析失败应选择获准兼容版本或独立新解释器，不静默放宽范围。

用户明确授权安装后，可在**项目独立环境**中安装可编辑基础包或研究 extra；不操作全局 Python、不复用历史 Linux Conda 构建号。未授权时只给方案与缺口，不自动执行安装命令。

## 3. 从本地到远端的 runbook

### 步骤 A：确认远端实际能取得哪个版本

1. 根 `.git/` 是唯一开发仓。记录本地 HEAD、dirty diff、上游来源和迁移映射。
2. 本轮不自动 commit/push。只有用户允许并实际提交/推送后，未来远端 clone 才包含重构；未提交内容不会随 clone 出现。
3. 用户选定远端地址/目录，自行 clone 已批准 revision。核对 HEAD、`src/caap/`、`plan/tasks.json`、`paper/sources/` 与根入口；不从 `.local/upstream/CAAP_code/` 启动旧脚本。
4. 私有数据/权重按许可挂载到 `.local/` 或显式批准的只读资产根，登记内容 hash；Git 没有同步这些资产不能当作丢数据后自动联网补齐。

### 步骤 B：先观察，不花训练预算

1. 核对 Python 版本并运行 §1 的 doctor/plan-check/unittest；保存 stdout/退出码与环境报告。
2. 读取获准资产 metadata、存储配额、CPU/RAM、scheduler 环境。默认不读 final 评分，不安全反序列化 `.pth`。
3. 汇总缺失数据、权重、依赖、训练/下载权限、allocation、总 GPU-hours 和实拍许可为一次 D0 消息；已有事实不再询问。
4. 继续无依赖的开发任务；不把资产阻塞变成“全项目只能等待”。

### 步骤 C：实现与验证开发门禁

按 F01–F45/02 的 S01–S12 断言推进；P0 输入、几何、面积、分母、独立评估、角色隔离和恢复均必须真实测试。先标准库和 CPU 小夹具，再获准 GPU 冒烟。

执行引擎必须通过 argv 白名单、path escape、并发领取、TTL、fencing、父 hash 改变和中断恢复测试。只有 doctor 与 plan-check 通过不能跳过此步。

### 步骤 D：取得资源并测量

在已授权 scheduler allocation 内做最小非 final 测量，记录单步/评估耗时、峰值显存、有效 microbatch、精度、warm-up、I/O 与最大存储。

按所有任务族展开 full 成本，包括识别器/特征/防御训练、补丁、派生评估、认证、重试和采集。给出有限 `GPU-hours` 与余额预留，不把“多卡很多”当无限执行授权。

### 步骤 E：冻结与启动 future 队列

D1 集中确认角色、搜索域、方法/基线、full 单元及预算边界。F20 负责数字全局冻结；认证、对抗训练、新架构和物理各自条件满足后形成独立 branch freeze，缺认证许可/旧实拍不阻塞无关数字开发。原作复现受阻也不阻塞独立 matched EOT/PGD，但原作状态仍保留在 full 对账。

冻结 manifest 的每个分支携带自身输入 hash、权限与确认集，已看 final 不能反馈其他分支设计。先 dry-run 对账，包含全部任务类型、N/A、阻塞和去重；仅派发自身门禁齐全且 allocation 有效的节点，未就绪分支仍为 full 缺口。

启动前按 04 校验 `runs/control/runner_registry.json`、`execution_prerequisites.json`、`dependency_bindings.json` 与科学manifest的hash一致、每条开发/证据边已绑定，缺映射或前提拒执行。F任务DAG通过plan-check不代表这些future执行产物已存在。

执行器只运行已审查 task_type 的固定 argv，不执行 manifest 中的任意 shell/Python；export_print 不自动调用打印机，run_original_attack 不强造原法没有的optimizer状态。普通 seed、技术重试和派生评估在授权边界内自动推进；科学变更/新费用集中升级。

## 4. 设备发现不等于资源授权

### 4.1 三层视图

- **物理视图**：GPU UUID、型号、显存、MIG 拓扑与实例 UUID；本地序号只是当前进程的别名。
- **进程可见视图**：`CUDA_VISIBLE_DEVICES`、容器映射以及可能的 UUID/MIG token；可见性可以被用户环境改写，不是可信授权凭据。
- **调度分配视图**：Slurm job/step、job GPUs/step GPUs、scheduler/cgroup 或管理员明确许可；运行必须在此集合内。

当前 doctor 恒定标记 `inventory_only=true/allocation_authorized=false`。它记录 SLURM/CVD 与硬件信息及缺失原因，不解析出有效租约，不证明 cgroup/allocation 已授权。正式调度需要在实际 worker 的 scheduler step 中重新验证分配范围与可见设备映射。

GPU CSV 清单包含物理 UUID/index、name、total/used/free MiB、利用率和 driver_version。可见性只保存 `CUDA_VISIBLE_DEVICES/NVIDIA_VISIBLE_DEVICES` 原始声明；CUDA 逻辑 index 可能不同于 nvidia-smi 物理 index，不得直接据此派发。

| **观察结果** | **结构化状态** | **解释** |
| --- | --- | --- |
| 工具缺失、超时、命令失败 | not_found/timeout/error；devices/device_count 为 null | 未知，不冒充没有 GPU |
| CSV 列/UUID/index/数值无效或重复 | parse_error；devices/device_count 为 null | 清单不可信，不从残缺记录猜资源 |
| 已知设备某指标 N/A/Not Supported | 指标 null、metric_status=unavailable，整体 partial | 其他合法指标仍保留 |
| 命令成功且 CSV 空 | no_devices、device_count=0 | 仅代表这次查询的空清单 |
| MIG 查询/解析失败 | 独立状态，devices=null | 不表示 MIG disabled |

MIG 通过单独的 `nvidia-smi -L` 查询记录 UUID/profile/device_index/parent_uuid；空清单不证明关闭、实例可租赁或有空闲额度。不得把父卡内存当 MIG 实例可用内存。

Slurm 只读白名单包括 JOB_ID/STEP_ID、JOB_GPUS/STEP_GPUS、GPUS_ON_NODE/GPUS_PER_NODE/GPUS_PER_TASK、CPUS_ON_NODE/CPUS_PER_TASK、MEM_PER_NODE/MEM_PER_CPU（实际环境键均有 `SLURM_` 前缀）；这些字符串不是独占租约证明。CPU/RAM/磁盘也是 host/filesystem 观察值，不保证等于 job/cgroup 限额或用户 quota。

`nvidia-smi` 的空闲显存/低利用率只说明观察时空闲。不能覆盖 CUDA_VISIBLE_DEVICES、抢占别人的 GPU、绕过 scheduler，或把宿主全部设备当用户授权。

### 4.2 Slurm 优先

有 Slurm 时由用户/集群规则获取 allocation，并使用相应 `srun` step 执行 worker；不在登录节点直接启动 GPU 训练，不凭环境字符串自行伪造 job。队列耗时、partition/QOS/account、抢占和时限均在资源预算内登记。

无 scheduler 时，必须有管理员/用户明确的设备 UUID/MIG 白名单和独占协调机制；不能自动回退到“取空闲 GPU”。allocation 或 UUID 映射不明确时标 BLOCKED_PERMISSION，集中通知。

## 5. future 租约、预算与并行

### 5.1 独占与 fencing

任务领取必须同时满足：依赖产物 hash 有效、计算门禁通过、资源预算预留成功、allocation 有效、设备租约可获。

每个物理 GPU/MIG 一个独占 lease，含 `lease_id,owner,task_id,run_id,parent_hashes,allocation_id,expires_at,heartbeat_at,fencing_token`。心跳频率/TTL 配置固定并入日志；过期不能直接杀陌生进程或给第二个 worker。

控制器先向 scheduler/进程表核验旧执行是否存在；存活但失联时暂停派发并协调隔离。确认撤销后才递增 fencing token 重授。旧 worker 即使继续计算，也无权发布产物或状态。父 hash 在领取与发布两次检查，防止上游被替换后陈旧结果入表。

物理 GPU 和其 MIG 子实例存在层级冲突，不能同授；不同 MIG 实例的并发必须来自明确 allocation。资源租约属于执行身份，不进入科学键；精度/AMP/TF32/world size 属科学语义，必须入键。

### 5.2 并发与 GPU-hours

默认通过独立任务并行使用多卡，每个任务单 GPU/MIG；优先并行无共享写入者、无依赖冲突的模型/seed/派生任务。不得因为硬件多而盲目加并发，必须同时考虑 CPU、RAM、I/O 和存储。

`GPU-hours = Σ(实际占用设备单位 × 占用时长)`，并保留设备类型/实例规格。MIG 的计费/折算规则来自获准资源政策并单列，不能与整卡时数混为同价。总预算含所有重试；运行前预留最坏合理任务成本，余额不足不领取新任务。

DDP 默认关闭。若 future 需求确实需要，先证明样本/有效 batch/优化器步数/归约/随机流/恢复等价，实测吞吐与开销，在配置中记录 world size 和精度。未测不能自动启用；增加 GPU 不能悄悄改变科学方法。

## 6. 中断、恢复与会话寿命

1. 停止派发，尽可能保存完整 epoch checkpoint；派生任务只发布完整校验分片。
2. 持久化 state/events、预算实耗、allocation 与活跃 lease。断会话并不意味着 worker 已停止。
3. 恢复时先读根仓 revision/dirty 指纹与冻结 manifest，再核验 scheduler job、设备映射、父 hash、checkpoint 和 fencing token。
4. 找到仍存活 worker 就接管观察，不能复制一个 run；旧 worker 已确认终止才按重试额度重建新 run_id。
5. 训练仅承诺已验证的完整 epoch 边界恢复；未实现 sampler/worker 中途状态前不声称任意 batch 精确续训。
6. 汇总前核对唯一 sample/pair/capture key、分片完整与旧 token/失效父链；进程退出 0 不自动意味着证据有效。

`tmux`/Python worker/scheduler job 保活不代表 LLM Agent 无限在线。已实现的受限执行器可继续冻结任务；遇到需 Agent 修代码或人类决策的情况只能落盘暂停。当前会话结束后不承诺自动继续未实现的科研计划。

## 7. 集中通知与安全退出

一次通知聚合同源故障、缺权限、缺数据/权重、安装问题、GPU-hours 余额、真实采集或稿件依赖，按“发现→证据→影响→推荐动作”给出可选方案。普通成功 run 不逐个打扰用户。

授权内同根因最多 2 次自动修复/重试，不能换目录重置计数。预算不足、安全越界或未知 allocation 立即停止新派发，不自动借卡/换云/装全局环境。

无可执行任务时生成部分覆盖与恢复条件，正常结束控制会话。`execution_exhausted` 表示可执行路径耗尽；只有 06 的原始 full 覆盖全部满足才是 `full_scope_complete`。
