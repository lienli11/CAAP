# CAAP 全量科研执行计划

**目标：把研究原型重构为可审计、可恢复、可逐条回应审稿意见的实验系统；以证据覆盖定义完成，不以 ASR 高低定义成功。**

计划版本：`caap-full-v2`，与 `plan/tasks.json` 和 full profile 的 `plan_version` 一致，编制日期：2026-10-14。默认 `scope=full`，不再受三周截止或旧核心实验数量约束。

**本轮只进行目录/包迁移、计划细化与标准库自检工具建设。** `doctor` 和 `plan-check` 是当前入口；P0 科学缺陷修复、正式队列、训练恢复、GPU 租约和科研实验均为后续任务，不能因迁移完成就声称已能自主完成科研。

## 2. 根仓与落位规则

| **位置** | **用途与规则** |
| --- | --- |
| 根 `.git/` | 唯一工作仓；未提交重构只在本地，不代表远端已经更新 |
| `src/caap/{attack,data,models,utils,tools,runtime}/` | 可维护源码；包模块为 `caap.*`，禁止再写回旧源码目录 |
| `paper/sources/{manuscript.pdf,review-letter.pdf}` | immutable 原始论文与审稿源，只读核验 hash，不改写/编译到此处 |
| `paper/revision/` | 取得合法稿件源码后才创建的派生修订稿/编译目录；来源只读引用，受 F44 写入授权约束 |
| `doc/`、`plan/` | 解释材料、科学合同与任务规格 |
| `archive/legacy/caap_revision/` | 合成权重、示例 CSV、历史 smoke；不是正式实验 |
| `archive/legacy/upstream/` | 原 `README.md/environment.yaml/run_attack_train.sh` 与来源记录；只供追溯 |
| `.local/upstream/CAAP_code/` | 旧源码完整本地副本，不发布；不是第二个开发入口 |
| `.local/` | 获准真实数据、权重和本地资产；通过台账与 hash 引用，不发布敏感数据 |
| `runs/<F任务ID>/<run_id>/`、`runs/control/` | F 分组执行产物与持久状态；F 是 owner/group，具体科学节点仍使用独立 task_id/scientific_key；只追加 |
| `reports/` | 经校验的覆盖、资源、统计与论文证据报告 |

`archive/legacy/migration.json` 记录上游 revision、dirty 状态、迁移映射与原条目指纹；不把目录迁移伪装成算法修复。`.local/upstream/CAAP_code/` 保留旧源码完整副本。不得删除 `.codebuddy/`、原资产或失败日志。

当前基础环境要求 `Python >=3.9`，基础安装不强制拉取 PyTorch；`[research]` 是可选依赖。macOS/CPU 可完成标准库自检与计划检查，CUDA 实验需要另行验证的 Linux/驱动/框架组合。精确 lock 仅在实际目标环境解析并测通后冻结，不直接照搬旧 Conda 导出的 Linux 构建号。

## 3. full 默认承诺

- Tongji、IITD、AISEC 三数据集与七模型，真实权重缺失时走合法识别器训练分支。
- 分类未定向与多个预注册真实目标；验证的本人拒绝、目标接受两目标，另设权限明确的 verification 专用损失分支。
- 原始基线与能力/面积/预算匹配适配；完整 `2³` 模块组合、随机/预训练控制。
- 面积、跨度、周长、方向、位置与结构代理；全模型迁移、集成留出、跨域与新架构。
- 对抗训练、PatchCleanser、CertMask 的适用性、真实防御训练/认证与攻击评估。
- 多设备、姿态、距离、光照、位置的真实采集与对照；16 条审稿意见和 H1–H5 的证据闭环。

旧 `8 pilot/51 train`、单模型优先、三周安排仅是 **core 观察/成本参考**。可以分批推进 full，但不能把后续格子删除后宣称 full 完成。外部数据许可、真实拍摄和稿件源码缺失时只能报告阻塞，不能承诺全自动获取。

## 4. 两类门禁

| **门禁** | **通过条件** | **未通过动作** |
| --- | --- | --- |
| G0：开发就绪 | 根仓/解释器/来源/路径与当前自检明确 | 可文档审查；未运行的测试不算通过 |
| G1：输入与渲染 | S01–S04 对应断言、负例、七模型合同 | 禁止科学训练 |
| G2：评估与恢复 | S05/S06/S09、任务类型与恢复/锁测试 | 禁止可入稿计算 |
| G3：计算就绪与冻结 | 对应数字/研究分支所需资产、角色、clean gate、冻结矩阵与许可/预算满足 | 只阻塞缺条件的分支；无关数字开发可继续，full 缺口保留 |
| G4：计算证据有效 | 逐格真实产物、所有 seed、统计与依赖校验 | 缺失/失败/阴性分别登记 |
| G5：full 交付 | 冻结 full 单元与 16/H1–H5 全部按合同决算，稿件/限制可追溯 | 部分完成，不以预算耗尽替代 |

`development_status=completed` 仅指实现和验收；`execution_status` 另记真实资产计算是否完成。开发测试可用合成夹具，但计算门禁不能用 synthetic/example 证据满足。

## 5. 一次性确认与自主推进

D0 集中确认：合法资产/许可、目标环境与 scheduler allocation、安装/下载边界、存储/时长、显式总 `GPU-hours`、真实采集与源码可得性。已能读取的事实不反复询问。

推荐先开展已获准的 **observational phase**：标准库自检、资产 metadata 审计和静态资源估计；不加载不可信 pickle、不训练、不读 final 评分，不要求先取得训练许可。需要安装、联网或新增资产访问时再集中提出缺口。

有测量许可后，使用非 final 小任务测耗时/显存并核算 full 预算。D1 集中确认协议、有限搜索域/次数、资源总额与计算授权；范围内普通任务与恢复不逐 run 再问。关键语义变更、权限缺失或余额不足才升级。

没有 GPU-hours 授权时训练预算为 0；“预算足够”“显存空闲”均不等于无限预算或任意 GPU 使用权。

## 6. 并发与长期执行

一个源文件同一时刻一个写入者；新模块须先指定所在 `src/caap/` 子包、测试与 owner，禁止任务自行开第二套项目根。每个派发包含 F/S ID、合同版本、允许路径、输入 hash、验收、预算和回报字段。

未来控制器可在持久状态和租约校验后恢复任务；这不等于当前已有队列实现。`tmux` 或 Python worker 保活不保证 LLM Agent 在断会话后继续决策。宿主 Agent 不可用时，只允许已获准冻结任务由受限执行器继续；需新决策则安全暂停。

## 7. 交接与完成状态

每个任务回报变更、测试命令/退出码/数量、环境、证据路径、协议影响、资源消耗与下一依赖。

- `full_scope_complete`：满足冻结 full 科学范围和证据标准，不要求每个假设得到正结果。
- `execution_exhausted`：当前预算、重试或可执行队列已耗尽；可能仍有大量未完成格子。
- `partial_blocked`：存在资产、许可、实现、采集或依赖缺口；列出恢复条件。

`CANCELLED_SCOPE` 只能形成明确缩小范围的交付，不能回填原 full 完成率。`report_status=READY` 只说明该报告合同通过，不等于全量科研完成、论文已接收或远端已有未提交代码。
