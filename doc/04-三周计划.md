## 2. 第一阶段：让未来远程机器可信

先固定实际含新布局的仓库提交，再在获准主机 clone。未提交的本地重构不会自动出现在 GitHub，不能让远程 Agent 根据旧提交假装已有新工具。

环境清点需要区分三个概念：

1. **看见 GPU**：驱动和工具能列出物理 GPU/MIG。
2. **被分配 GPU**：Slurm、容器映射或管理员/用户明确授权哪些 UUID 可用。
3. **能承载任务**：指定 PyTorch 构建、实测显存和耗时证明该模型可运行。

只有三者都满足才派发训练。空闲显存不是授权，八张卡也不意味着必须 DDP；默认多个独立任务各占一个获准设备，先验证正确性和吞吐。

## 3. 第二阶段：先建基础，再做公平搜索

F06–F19 覆盖数据角色、真实识别器、辅助特征、像素/几何/面积、分类与验证目标、统计、产物恢复和测试隔离。

这些任务有真实实现前置条件，但许多负例和基础设施可先用合成夹具开发。夹具通过只能说明接口和数学行为，不产生论文数字。

然后 F20 在预设开发空间中自动搜索：预算、候选、早停、选模和全部 trial 留档。主方法和基线给予可解释的调优资源，而不是只优化 CAAP。

搜索可以根据开发集反馈继续，但必须有限、可追溯，并使用单独选择/确认层。最终测试结果不回流调参。

## 5. 怎样并行，又不会互相污染

源码开发与实验运行是两种并行。前者按文件所有权和分支集成，后者按冻结代码、依赖、设备租约和资源预算。

控制 Agent 维护状态；worker 只执行已注册任务；评价 Agent 只读冻结产物；审查 Agent 验收证据；稿件 Agent 汇总结果。worker 失联后必须核对原进程和 fencing token，不能租约超时就启动第二份同任务。

进程、文件和配置必须绑定同一版本。正在写源码时启动 GPU job，必须使用已冻结快照，避免一个任务跑到一半导入新版本。

新实验产物只进 `runs/`，报表只进 `reports/`。跨会话从 `runs/control/` 恢复，不能靠模型记忆推断上次跑到哪里。

## 6. 观察结果与“继续试验”的边界

**允许自动继续：** 开发集上的预注册有限搜索、技术故障修复、已冻结矩阵剩余单元、因实现修正而一致失效的重跑。

**不允许自动继续：** 为了让十字获胜而换测试模板、为了显著性追加 seed、最终测试低 ASR 后换目标、将无作用模块调到出现有利结论才停止。

最终测试解封后，技术错误可以复现、审查并修正；所有受影响方法/种子/条件一起重算，旧结果保留。新的科学设计必须新版本，并有新的确认依据或明确降为探索性，不能改名“补跑”。

## 7. 关键时刻才通知用户

- **D0**：真实资产/使用许可、可用主机与设备、数值资源上限、稿件源码。
- **D1**：开发结论形成正式冻结，或必须改变科学范围、能力、预算与数据政策。
- **D2**：可追溯证据要求改变论文主张，包含负结果和适用性限制。
- **D3**：自动修复耗尽、权限阻塞、安全/资源边界即将突破。

正常进度、日志和运行状态落盘。通知给“事实、证据、影响、建议和所需决定”，不逐步打扰，也不在阻塞时无限后台空转。

## 8. 完成不是单一布尔值

- **实现完成**：接口、正负测试、独立审查通过。
- **实验完成**：预注册单元有有效结果，包含阴性结果，全部来源可复核。
- **审稿回应完成**：每条意见对应修改、证据、稿件位置与限制。
- **full 范围完成**：原始承诺的全部研究分支与实拍要求均满足，或事先定义的客观不适用得到独立验证。
- **执行暂时耗尽**：所有可做的工作已做，剩余被资产/许可/预算阻塞。这不是 full 完成。

若用户决定缩范围，可以交付 partial 或新的 core 范围，但原始 full 覆盖账本仍保留未完成项。不能删除困难任务再宣布全部完成。
