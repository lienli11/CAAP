# 仓库结构、迁移边界与验证记录

**这次重构解决“代码和证据放哪里、未来 Agent 从哪里开始”，不冒充已经完成算法修复或真实论文实验。**

记录日期：2026-10-14；包版本：`caap-research 0.2.0`。原归档提交 `278e371` 仅包含旧布局；远程启动须固定实际包含本文件及 `src/caap/`、`plan/tasks.json` 的重构提交，发布状态以 GitHub 分支和本地提交核验为准。

## 1. 为什么采用这套结构

原来存在工作区根仓和内层 `CAAP_code/.git`，代码、PDF、合成权重、旧计划和执行脚本并列；部分入口在导入时更改 CWD 或插入路径，换机器后容易读错相对文件。

现在将源码统一为 `src/caap/` 可安装包；文档保持 `doc/` 与 `plan/`，原始材料独立冻结，新运行默认不进 Git。

| **旧位置** | **新位置** | **迁移方式** |
| --- | --- | --- |
| `CAAP_code/{attack,data,models,utils,tools}` | `src/caap/` 对应子包 | 保留核心算法与模型层级，修改 import/入口和显式路径 |
| 根目录两份 PDF | `paper/sources/manuscript.pdf`、`review-letter.pdf` | 原字节不变，原名/hash 记入清单 |
| `caap_revision/` | `archive/legacy/caap_revision/` | 历史文件原字节不变，不改旧配置路径 |
| 原环境/README/Shell | `archive/legacy/upstream/` | 原样保留，只用于追溯 |
| 内层完整 Git 工作树 | `.local/upstream/CAAP_code/` | 本机保留原 HEAD、修改和 untracked 文件，不随新 clone 发布 |
| 新运行与报表 | `runs/`、`reports/` | 独立科学身份、来源和恢复状态，默认 Git 忽略 |

迁移清单：[archive/legacy/migration.json](../archive/legacy/migration.json)。新目录角色登记：[configs/repository-layout.json](../configs/repository-layout.json)。

## 2. 已经实现的能力

- `python -m caap` 与安装后的 `caap` 命令统一派发，包根和标准库工具不强制导入 PyTorch。
- `doctor` 清点解释器、依赖、CPU/RAM/存储、GPU UUID/MIG 与可见性声明；不分配 GPU，也不把空闲资源当授权。
- `plan-check` 校验 45 个 F 任务、DAG、阶段、字段、spec、路径和 16 条意见/H1–H5 覆盖，提示潜在写入冲突。
- 旧训练、预训练、物理报告明确命名 `legacy-*`，需要显式开关；缺路径、权重、不安全入口配置和已有输出会被拒绝。
- `make-synthetic` 默认只生成标记为 synthetic 的条纹数据，训练需要额外显式开关；不会默认在安装目录写文件。
- `.gitattributes` 固定源码 LF，冻结档案禁用文本转换；避免 Git 换行配置使原始证据 hash 失真。
- 目录、文档链接、原始字节、导入副作用、命令行为与数值迁移均有测试；CI 配置已加入，但远端 CI 尚未实际运行。

这些工具**不包括正式 GPU 调度器或完整科研执行引擎**。F04/F05/F18/F20 等任务仍需实现、验收和资源授权。

## 3. 与原行为的有意差异

CLI 相对路径现在相对调用者 CWD，支持 `~`；不再切换到源码目录，也不再按 hostname 猜服务器数据路径。

旧入口新增显式 legacy 确认、输入存在性、禁止随机识别器、验证比例/归一化保护与输出不覆盖。旧产物标记 unverified、非论文可用，防止被新收集器误用。

这些是可移植性和入口保护变化，不是新攻击算法。旧核心几何/alpha、选模、统计和验证链的缺陷仍由 F11–F19/F30/F42 按版本化合同修复。

未来算法升级后，受影响模块不再满足迁移的“逐字/逐数值不变”断言是合理的。必须通过新语义回归与独立审查更新测试基线，原始档案/hash 不变；不能为通过迁移测试而恢复旧 bug。

## 5. 审查后修正的问题

- 缺研究依赖时，统一 CLI 提供安装与 legacy 边界提示，不直接用导入 traceback 代替帮助。
- 路径检查不能只信通配符前缀；已增加现存符号链接/逃逸/循环及扫描上限的保守处理。
- 无效 JSON 的异常字符不应使校验器崩溃；错误输出使用可安全编码的结构化形式。
- `doctor --probe-torch` 在隔离子进程运行，报告需说明 user-site/PYTHONPATH 的区别，不能与普通 import 等同。
- 核心数字冻结、原作复现、认证与物理分支分别设置前置条件；外部资料缺失不得无谓阻塞已获准的无关任务，但最终 full 账本保留缺口。
- 修订稿进入 `paper/revision/`，原 `paper/sources/` 始终只读。

### 延迟审查消息的落盘复核

收到异步历史审查汇总后，重新核对了实际文件，而未采用过期行号或 DONE 消息作为依据。确认 F23 的原作依赖、F44 的写目录以及控制文件归属已修；另发现 F09 的分片和任务索引尚未完整区分 registry-ready 与逐模型真实 gate，已补齐并完成定点独立复核。

现已明确：F09 的 21 项状态表允许缺资产条目，真实洁净验证由独立 `validate_recognizer` 节点生成局部 model-entry/gate。Tongji 单元前提齐全而 AISEC 缺失时只运行前者，full 仍为 INCOMPLETE；后补 AISEC 不改变未变 Tongji 的科学键。开发边使用统一 requires_stage，科学节点以 `{task_id,entry_hash}` 引用独立执行前提文件。

此次复核后的本地 105 项现有测试再次全部通过，45 项文档 DAG 无环、16 条意见及 H1–H5 无覆盖空缺；定点审查结论为合同一致。**这些结果不表示未来局部调度、GPU 队列或真实实验已经实现/运行**，新增的调度场景仍是 F 任务需实跑的验收。该轮复核未启动训练，代码发布与后续科研执行分别登记。

## 6. 新 Agent 的接力线

从 [计划入口](../plan/README.md) 和 [远程规范](../plan/05-远程启动与资源调度.md) 开始，先运行实际存在的检查工具，再领取依赖已满足的 F 任务。

需要补齐的外部条件：实际含本次重构的远端 commit、真实数据/许可与权重或训练配方、远程设备分配与数值预算、实拍原图/新采集许可、稿件源文件。

自动化负责已授权范围的实现、测试、观察、有限纠错、恢复与对账；不能自动创造许可、实拍或支持创新的结论。完整计划的价值是使负结果、失败和缺口都可追溯，而不是保证所有假设成立。
